# 站①驗收條件：批次一（地基）

寫於 2026-09-05。這一批只做地基，不寫任何正式文案。
頁面可以是佔位內容，但路由、語言前綴、部署、網域必須是真的。

**為什麼先做這批**：後面每一件事都要有地方放、有網址可以驗。
地基沒立起來，內容做得再好也驗不動。

---

## 一、Repo 與工作區

| # | 條件 | 怎麼驗 |
|---|---|---|
| A1 | `main` 分支存在，本機與遠端同步 | `git status -sb` 顯示 `## main...origin/main` 且無落差 |
| A2 | `.gitignore` 擋住 `node_modules/`、`dist/`、`.astro/`、`.env`、`.wrangler/`、`.DS_Store` | 跑完 `npm install` 與 `npm run build` 之後，`git status` 仍然乾淨 |
| A3 | `README.md` 寫明這個 repo 是什麼、網址、與另外兩個 repo 的分工 | 人工讀過 |

## 二、Astro 骨架

| # | 條件 | 怎麼驗 |
|---|---|---|
| B1 | `npm run build` 成功，產出靜態檔 | 指令回 0，`dist/` 有 HTML |
| B2 | 五個路由都存在且回 200：`/zh/`、`/zh/why`、`/zh/pipeline`、`/zh/start`、`/zh/about` | 本機預覽逐一開啟，或 `curl -o /dev/null -w "%{http_code}"` 五次 |
| B3 | 根目錄 `/` 會轉到 `/zh/` | 開 `/`，網址列停在 `/zh/` |
| B4 | 每頁 `<html lang="zh-Hant">` | 檢視原始碼 |

## 三、保留英文擴充的六件事

這六件現在做幾乎不花時間，之後補要拆掉重來。**這一批不做英文內容，只做架構。**

| # | 條件 | 怎麼驗 |
|---|---|---|
| C1 | 網址一律帶語言前綴，沒有任何頁面直接掛在根目錄底下 | `dist/` 底下除了轉址頁，HTML 都在 `zh/` 資料夾內 |
| C2 | 內容檔放在 `src/pages/zh/`，一頁一個 `.md`，檔名即網址 | `ls src/pages/zh/` 看到五個檔，檔名對得上五個路由 |
| C3 | 導覽與按鈕等介面字串抽在獨立 JSON，版型檔裡沒有寫死的中文介面字串 | `grep` 版型檔找不到導覽文字，只在 JSON 裡找得到 |
| C4 | 頁面有 `hreflang` 標記（目前只有 zh 一個值） | 檢視原始碼 |
| C5 | 加一個英文頁只需要三個動作（`LOCALES` 加代號、新增 `src/i18n/en.json`、新增 `src/pages/en/*.md`），不必改版型 | 用拋棄式測試檔實證：照這三步加 `/en/about`，看它出不出得來，驗完刪掉 |
| C6 | 留言資料表的 schema 已含 `locale` 欄位 | 看 schema 檔（資料表這一批可以先不建，但 schema 要寫好） |

## 四、部署與網域

| # | 條件 | 怎麼驗 |
|---|---|---|
| D1 | Cloudflare Workers 接上這個 repo，push 到 `main` 會自動部署 | 推一次，看 Workers Builds 的部署紀錄 |
| D2 | `https://civictech-guide.claire-cheng.com/` 回 200，憑證有效 | `curl -I https://civictech-guide.claire-cheng.com/` 不報憑證錯誤 |
| D3 | `http://` 自動轉 `https://` | `curl -I http://civictech-guide.claire-cheng.com/` 回 3xx 且 Location 是 https |
| D4 | 每頁的 `og:url` 與 `canonical` 指向新網域的對應網址 | 檢視五頁原始碼，網址逐一對照 |
| D5 | 隨便打一個不存在的網址會拿到自己的 404 頁，不是 Cloudflare 的預設錯誤畫面 | `curl -o /dev/null -w "%{http_code}" https://civictech-guide.claire-cheng.com/沒有這頁` 回 404，內容是站上的 404 頁 |

## 這一批的站④怎麼跑

**跑 `/code-review`，不派 `acceptance-reviewer`。**

理由：`acceptance-reviewer` 的價值是「沒看過產出過程的陌生人視角」，
而這一批的產物是設定檔與空骨架，沒有讀者要讀的東西，陌生人視角無從發揮。
到批次二（內容上站）恢復完整雙審查，那時候才有文案可以被挑錯。

## 修訂紀錄

- 2026-09-05：網域由 `civictech.claire-cheng.com` 改為
  `civictech-guide.claire-cheng.com`。前者早就接給另一個站
  （global-civic-tech，全球公民科技動態），而且已經寫進發布出去的文章連結裡，
  搶過來會弄壞既有連結。**教訓：推薦網域前先查那個子網域有沒有人住**
  （`dig +short <子網域> @<權威 NS>`），不要只查要退場的那一個。
- 2026-09-05：部署平台由 Cloudflare Pages 改為 Cloudflare Workers。
  Cloudflare 已把 Pages 標為 legacy，新建站走 Workers 才是現行做法，
  批次三的留言區 API 也能跟靜態檔住在同一個地方。D1 的敘述隨之更新，
  並補一條 D5 驗自訂 404 頁。
- 2026-09-05：C2 與 C5 的路徑由 `content/zh/` 改為 `src/pages/zh/`。
  原本寫 `content/` 是照一般靜態網站的習慣，實作時改用 Astro 的
  `src/pages/`：markdown 檔放進去就直接是一個頁面，檔名即網址，
  不必另外設定資料集。原則沒變（一頁一檔、語言資料夾分開），只是路徑名不同。
