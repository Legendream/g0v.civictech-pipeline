## D4 源頭規則（2026-09-07 定案，全文抄錄）

acceptance-reviewer 驗收批次三時指出：這份規則先前只寫「已在 2026-09-07 的對話裡給過 Claire」，沒有留下書面全文，沒辦法逐條核對。以下從那次對話的 session 記錄找回、抄錄全文，之後驗收就以這裡為準，不用再去挖記錄。

**一、必須讓讀者知道的事，一件都不能少**

1. 留言送出後立刻公開，不經審核
2. 不需要註冊、不需要留 email。只有留言內容是必填，暱稱可留空，留空顯示為「匿名」
3. 留言存在這個網站自己的資料庫，沒有經過第三方留言服務
4. 不記錄 IP，站上沒有追蹤碼
5. 留言是公開的，任何人都讀得到，所以不要在裡面填個人資料
6. 站方保留把留言下架的權利，下架後不再顯示
7. 想撤下自己的留言怎麼辦：因為留言不綁定任何身分，沒辦法確認哪一則是你的。做法是到 GitHub 開一則議題，附上留言內容與大概的時間
8. 目前只有中文留言區

**二、下架標準**：廣告或大量重複張貼、與這個網站主題無關、人身攻擊或歧視、洩漏別人的個人資料、違法內容。

**三、不能寫的**：不承諾回覆時間；不寫「留言即代表同意本站使用者條款」（這個站沒有使用者條款）；不出現技術名詞（資料庫產品名、binding、XSS）；不用程度副詞；全文無破折號；不確定的事實用具名佔位標示。

**四、語氣與篇幅**：具體、假設讀者沒有背景知識；正向表述優先，下架標準一句話帶過，不要寫成禁令表；長度約 150 到 250 字；能單獨讀懂。

**這批實際寫法跟規則的差異，記著給下一次改文案的人看**：規則裡的第 1 到 8 件事沒有全部逐條列成清單，是揉進兩段連續的白話文字裡（about.mdx「意見回饋與提問」節前兩段）；「暱稱可留空顯示匿名」用介面上的 placeholder 文字帶過，沒有寫進政策段落本身，實際行為在 `src/i18n/zh.json` 的 `comments.namePlaceholder`。這是為了控制在 250 字內做的取捨，不是漏寫。
