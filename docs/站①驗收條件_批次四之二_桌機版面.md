# 站①驗收條件：批次四之二（桌機版面寬度與對齊）

寫於 2026-09-08，批次四合併之後。這一批只動版面尺寸與對齊，不動任何一句文案、
不動配色、不新增元件。

## 為什麼要做這批

批次四照設計交接包做，內容固定 680px。交接包標的是 Hi-fi、要求照做不要自由發揮，
但那份稿子沒有在桌機寬螢幕上檢視過：1440px 視窗下內容只佔 47%，1920px 只佔 35%。

第一次修的時候我改成雙軌（段落 700／卡片 920），但讓兩者**各自置中**，
於是左緣差了 150px，標題看起來相對下方的卡片內縮。那個對齊 bug 是這一輪
自己製造的，不是批次四遺留。

技能庫（`ui-ux-pro-max`）給這個站的產品類型是 Knowledge Base/Documentation，
建議風格 Minimalism + Swiss Modernism 2.0，後者的核心就是嚴格的對齊軸。

## 定案的三件事

| 議題 | 決定 | 依據 |
|---|---|---|
| 軌道寬度 | 軌道 1080 / 段落 720 | 段落 720px 在 17px 字級下每行約 34 個中文字，中文舒適行長 35–45 字，720 在下緣；再窄行長偏短，再寬卡片會鬆散 |
| 圖示位置 | 內嵌（不外掛到留白） | 外掛版圖示會跟標題脫節，且窄螢幕沒有留白可掛，1024px 上下會變成兩種排法 |
| 站名 | 20px / 字重 700 | 技能庫 `font-scale` 要求級距一致（12/14/16/18/24/32），19 不在級距上 |

---

## 一、對齊（這一批的重點）

| # | 條件 | 怎麼驗 |
|---|---|---|
| A1 | 頁首站名、段落、H2 標題列、卡片格線、表格、時間軸、頁尾，左緣全部落在同一個 x 值 | 1440px 下用 `getBoundingClientRect().left` 逐一量，數值必須相同 |
| A2 | 段落靠左對齊於軌道，不是自己置中 | 段落左緣等於卡片左緣，右緣小於卡片右緣 |
| A3 | 寬元素（卡片、表格、時間軸）吃滿整條軌道 | 卡片格線寬度等於 `--wide` |
| A4 | 1920px 下同樣對齊 | 同 A1，換寬度再量一次 |

## 二、行長與尺寸

| # | 條件 | 怎麼驗 |
|---|---|---|
| B1 | 段落**滿行**容得下 35–45 個中文字 | 量單一中文字的實際佔寬，再除段落寬度。不可用「總字數除以行數」：最後一行不滿會把平均拉低。混入數字與英文的段落字數會虛高（半形），以視覺行長為準 |
| B2 | 站名 20px、字重 700；導覽 14px；H1 2.2rem | 讀 computed style |
| B3 | 站名明顯大於導覽、明顯小於頁面 H1 | 三者字級遞增且互不接近 |

## 三、四個寬度都不能破

| # | 條件 | 怎麼驗 |
|---|---|---|
| C1 | 375 / 768 / 1440 / 1920 四個寬度，六個頁面都沒有橫向捲軸 | 逐一量 `scrollWidth > clientWidth` |
| C2 | 375px 下卡片格線收成單欄 | 量卡片寬度等於容器寬度 |
| C3 | 375px 下表格與程式碼區塊仍是內部捲動，沒有被新格線弄壞 | 量 `.table-scroll` 與 `pre` 的 `scrollWidth > clientWidth` |
| C4 | 768px 下軌道收在視窗內，左右仍有至少 24px 邊距 | 量卡片左緣不小於 24 |
| C5 | 每個斷點下卡片內文一行至少容得下 18 個中文字 | 量卡片內文可用寬除以單字佔寬。三欄擠在平板寬度會掉到 12 字 |

## 四、批次四的成果不能退步

| # | 條件 | 怎麼驗 |
|---|---|---|
| D1 | 文案一字未改 | 抽改版前後純文字 diff，零差異 |
| D2 | 深色模式四項仍然成立 | 跟隨系統、手動覆蓋、重整不還原、表頭對比 |
| D3 | 捲動導覽仍然標對段落 | CDP 驅動真實 Chrome，三頁逐段捲動 |
| D4 | 零第三方請求 | 掃全部 HTML |
| D5 | 建置成功、五個路由都在、正文仍在靜態 HTML 裡 | `npm run build` 加 curl |

# 後續調整：改為單欄置中，字級整體放大

2026-09-08。前一節的雙軌左軸解決了對齊，但帶出新問題：純文字的區塊
（H1、段落、摘要卡、長條圖）寬 720，軌道寬 1080，右邊沒有東西補，
1254px 視窗下實測左留白 87、右留白 447。首頁上半段沒有卡片，整片看起來偏左。

## 為什麼改成單欄

「不要太窄」「置中」「對齊」三件事，在中文行長上限之下無法同時成立——
除非把字放大。單欄時置中與對齊不再衝突，剩下的變數只有欄寬與字級。

中文舒適行長 35–45 字。17px 字級下 45 字就是 765px，這是硬上限；
要更寬只能放大字級。選定 **860px / 19px**（滿行 45 字）。

## 這不是改兩個數字

全站有 11 個檔案、24 處寫死的 px 字級。只動 body 不動它們，
結果是內文變大、其他元件相對縮水。因此同時做兩件事：

1. 所有字級等比放大（×19/17 ≈ ×1.118）
2. 收成 CSS 變數，下次調字級改一行，不必再翻 11 個檔案

## 字級級距

| 變數 | 值 | 用在哪 |
|---|---|---|
| `--fs-3xs` | 13px | 語言膠囊 |
| `--fs-2xs` | 15px | 圖說、頁尾、卡片編號、明暗切換鈕、時間軸兩欄 |
| `--fs-xs` | 16px | 導覽、捲動導覽、圖例、收合鈕、FAQ 答句、長條圖標籤、表格、程式碼 |
| `--fs-sm` | 17px | 卡片標題與內文、摘要卡、FAQ 問句、時間軸站名 |
| `--fs-md` | 18px | 作者介紹 |
| `--fs-body` | 19px | 內文 |
| `--fs-lg` | 22px | 站名、時間軸編號 |

標題等比放大以維持層級：H1 2.2→2.45rem、H2 1.4→1.55rem、H3 1.08→1.2rem、
H4 1→1.1rem；窄螢幕的 H1 1.75→1.95rem、H2 1.25→1.4rem。

### 一個沒有修、交給 Claire 判斷的取捨

桌機三欄卡片只有 277px、一行 14 個中文字，**比 768px 兩欄的 18 字與
375px 單欄的 16 字都窄**，形成「螢幕愈大卡片愈擠」。

這是選定單欄 860 的必然結果（三欄平分 860 就是 277），不是程式錯誤。
換算設計稿原本的 680px 單欄約為 11 到 12 字，所以相對設計稿是變寬的；
但相對上一版 1080 雙軌的 21 字是變窄的。

要改善只有三條路，都有代價：三欄改兩欄（版面與設計稿不同）、
卡片字級單獨縮小（破壞剛建立的字級級距）、卡片獨立吃更寬的軌道
（純文字區塊又會偏離中央，等於退回這次要修的問題）。
