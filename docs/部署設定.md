# 部署設定（Cloudflare Workers）

這個站部署在 Cloudflare Workers，專案叫 **`g0v-civictech-pipeline`**。

**這份文件存在的理由**：下面這些設定住在 Cloudflare 後台，不在這個 repo 裡。
沒寫下來的話，下次要改的人（包括半年後的你自己）只能靠點進去翻。

最後更新：2026-09-09

---

## 後台的四格設定

在 Cloudflare 後台的 Workers & Pages → `g0v-civictech-pipeline` →
**Settings** → 右側目錄按 **Builds** → Build configuration：

| 欄位 | 值 | 說明 |
|---|---|---|
| Build command | `npm run build` | Astro 把五頁產成 HTML 放進 `dist/` |
| Deploy command | `npx wrangler deploy` | 把 build 好的東西送上去 |
| Version command | `npx wrangler versions upload` | 預設值，給非 production 分支的預覽版用 |
| Root directory | `/` | 專案就在 repo 根目錄 |

**Deploy command 不是輸出目錄。** 這一格的內容會被當成一行 shell 指令執行，
填 `dist` 會得到「找不到這個指令」。輸出目錄寫在 `wrangler.jsonc` 的
`assets.directory`，wrangler 自己會去讀。2026-09-05 第一次部署就是這樣掛的。

## 名字必須兩邊一致

Cloudflare 上的 Worker 叫 `g0v-civictech-pipeline`（建立時從 repo 名自動帶的），
`wrangler.jsonc` 的 `name` 也必須是這個。

不一致的話 `wrangler deploy` 會照設定檔的名字**另外生一個新的 Worker**，
而不是更新現有那個，結果是兩個 Worker、自訂網域接錯邊。
Worker 建立之後改不了名，所以要改只能改設定檔那邊。

## 自訂網域寫在設定檔，不在後台

`civictech-guide.claire-cheng.com` 宣告在 `wrangler.jsonc` 的 `routes`：

```jsonc
"routes": [
  { "pattern": "civictech-guide.claire-cheng.com", "custom_domain": true }
]
```

部署時 wrangler 會自己建立自訂網域與 DNS 記錄。要換網址就改這一行，
不要去後台的 Domains 頁點，兩邊都改會打架。

2026-09-05 在後台的 Domains 頁按過兩次新增都沒有成功建起來
（權威 NS 查不到記錄），原因沒查出來。改走設定檔之後就通了。

## Git 連線斷掉的徵兆

Settings → Builds 區塊如果出現藍色橫幅
「This project is disconnected from your Git account」，代表 Cloudflare
收不到 GitHub 的推送通知，**merge 之後不會觸發任何 build**。

徵兆是：你明明 merge 了，但 Deployments 頁最新一筆的時間還停在上一次。
修法是按 Git repository 那一列的 **Manage**，回 GitHub 確認這個 repo 有授權給
Cloudflare 的 App；真的不行就 **Disconnect** 之後重連。

## 不要用 Retry build 來套用新設定

Retry 是重跑**當初那個 commit**。如果失敗的原因已經在後續的 commit 修掉了，
Retry 會拿舊內容再失敗一次。要用最新的 `main` 跑，就推一次新的 commit
（正常走分支加 PR 就會觸發）。

## 這個 Worker 沒有分支隔離的預覽環境

專案 `CLAUDE.md` 原本假設「分支推上去會產生獨立的預覽網址，正式網域只跑 `main`」，
這個假設對 Cloudflare Pages 成立，但**這個專案用的是 Cloudflare Workers，行為不一樣**。

一個 Worker 只有一份「目前正式在跑」的版本。不管是：

- 推 commit 到非 production 分支（即使 Settings → Builds 有勾選
  「Builds for non-production branches」，那只保證會**建置**，不保證只影響預覽）
- 或是直接在後台「Variables and secrets」按 **Add and deploy**

都可能直接更新這個 Worker 的正式版本，也就是直接生效在 `wrangler.jsonc` 裡
`routes` 宣告的正式網域上，不會像 Pages 那樣自動切出一個跟正式站分開的預覽網址。

2026-09-09 批次三上線時就是這樣：`comments-section` 分支的程式碼還沒開 PR、
沒經過 merge，就已經在 `civictech-guide.claire-cheng.com` 上跑了。

**How to apply**：往後要在「正式網域看不到」的前提下驗證改動，要嘛用
`wrangler dev` 在本機跑，要嘛先去查證這個 Worker 有沒有另外設定
Environments／Preview URLs（目前沒有）。不要預設分支或後台編輯是安全、
不影響正式站的操作。

## Cloudflare Workers Builds 沒有「建置期環境變數」

Settings → Variables and secrets 那個清單，只給 Worker **執行期**用
（`worker/index.js` 裡用 `env.X` 讀的那種）。一開始以為這裡也能餵給
Astro 的 `npm run build`（`import.meta.env.PUBLIC_X`，會被寫進靜態 HTML
的那種變數），試了兩次都不行：

1. 後台加完變數按「Add and deploy」，那只是把既有的建置結果重新套上
   新的 binding，沒有重跑 `npm run build`
2. 改成先在後台把變數存好，再推一次 git commit 觸發真正的 build——
   結果 HTML 裡還是沒有這個值

代表 Cloudflare Workers 的 Git 建置流程，**沒有提供任何管道**把後台設定的
值餵給 build 階段的 Astro（不像 Cloudflare Pages 有獨立的「Build
environment variables」）。

**How to apply**：Astro 建置期要用的值，不要指望能從 Cloudflare 後台設定，
直接寫進程式碼／版控裡（前提是這個值本來就不是機密，例如 Turnstile 的
Site key——它本來就會印在頁面原始碼裡給訪客看，寫進 git 不會多暴露什麼）。

## Secret 類的值，用 `wrangler secret put`，不要用後台網頁

真正的機密（例如 Turnstile 的 Secret key）不能寫進程式碼，本來想走後台
**Variables and secrets** 網頁介面設定，結果卡了很久：後台存了值、畫面也
顯示「Value encrypted」，但 Worker 執行期讀到的 `env.TURNSTILE_SECRET_KEY`
一直是空的——查過是不是名稱打錯、是不是忘記按存檔（後台這個存檔按鈕會用
一條浮動的「Unsaved changes」黑色提示條，很容易滑過去沒看到）、是不是要
等新版本部署，都試過，還是讀不到。

最後改用終端機的 CLI 指令才成功：

```bash
npx wrangler secret put TURNSTILE_SECRET_KEY
```

跑起來會提示貼上值（畫面不會顯示貼的內容，這是正常的），成功會印出
`✨ Success! Uploaded secret TURNSTILE_SECRET_KEY`。這樣設完，Worker
馬上就讀得到，不用額外觸發部署。

**How to apply**：這個專案的 Secret，一律用 `wrangler secret put <NAME>`
設定，不要用後台的 Variables and secrets 網頁介面——後台介面在這個專案上
試過確實不可靠，原因沒有查清楚（可能跟這個 Worker 是透過 Git 連動的
Workers Builds 部署、不是單純手動 `wrangler deploy` 有關），但既然有可靠
的替代方案，不值得再花時間查根因。

## 留言區（批次三）需要的後台設定

程式碼與 `wrangler.jsonc` 的 binding 已經寫好，但下面四件事都要用**妳自己的 Cloudflare 帳號**做，這個環境裡的 `wrangler` 沒有登入權限，做不了：

1. **建 D1 資料庫**：終端機跑 `npx wrangler login` 登入，再跑
   `npx wrangler d1 create g0v-civictech-comments`。
   指令會印出一組 `database_id`，貼進 `wrangler.jsonc` 的 `d1_databases[0].database_id`
   取代裡面的佔位文字
2. **套用資料表結構**：`npx wrangler d1 execute g0v-civictech-comments --remote --file=./db/schema.sql`
3. **開一個 Turnstile widget**：後台 **Turnstile → Add site**，網域填
   `civictech-guide.claire-cheng.com`。會拿到兩把金鑰：
   - **Site key**（公開，不是秘密）：直接寫進
     [Comments.astro](../src/components/Comments.astro) 的
     `turnstileSiteKey` 常數，不要指望 Cloudflare 後台的環境變數（見上一節
     「Cloudflare Workers Builds 沒有建置期環境變數」）
   - **Secret key**（不能外流）：終端機跑
     `npx wrangler secret put TURNSTILE_SECRET_KEY`，貼上值。不要用後台的
     Variables and secrets 網頁介面（見下一節「Secret 類的值，用
     wrangler secret put，不要用後台網頁」），這是
     `worker/index.js` 拿去跟 Cloudflare 核對留言是不是機器人送的
4. 上面四件事沒做完之前，留言表單看得到但送不出去（Turnstile 驗證會失敗），
   讀取留言的 API 也會因為 D1 還沒接上而報錯。這是預期中的，不是壞掉
