# 怎麼開始

## 開始前你要準備什麼

- **一個裝得起來的 AI 工具**。哪些用得起來、哪些還沒測，見下面那張表
- **你想寫的文章素材**：連結、文件、訪談筆記。先整理好即可，不用先讀完
- **一篇你喜歡的範文，或你以前寫過的文章**：當作風格的起點。沒有也能開始，AI 會套上一份預設寫作原則
- **想清楚這篇要給誰看**：寫給同溫層內行人，跟寫給第一次接觸的人，整篇的結構會不一樣。這件事越早定越省事

## 哪些工具用得起來

| 工具 | 怎麼裝 | 我們實測到什麼 |
|---|---|---|
| claude.ai（Pro 以上方案） | 上傳壓縮檔裝成 Skill，見下面的路徑一 | 2026-09-02 實測可用。用路徑一教的那句話實測，回覆最後一行出現「下一站：」，四種說法都叫得出來 |
| Claude Code、Antigravity 等讀得到檔案的工具 | 把整包檔案抓到你電腦上，見下面的路徑二 | 這個成績是 **Antigravity** 在 2026-08-18 跑出來的：裝得起來，流程跑得完，**但交付前那道獨立驗收不能省**，當時沒過的地方集中在事實查核。**Claude Code 沒做過同一種測試**，不是不能用，只是還沒測 |
| ChatGPT、Gemini | 自己建一個 Custom GPT 或 Gem，把流程檔上傳成知識檔 | **我們沒有實測過**，所以不算驗證過的路徑。可以把那包裡的驗收清單當成自己用的人工檢查表 |

上傳自訂 skill 從 Pro 方案開始，所以路徑一需要 Pro 以上（依 [Claude 開發者文件](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/overview)，
2026-09-02 查證）。

## 兩條路徑，挑一條

- **路徑一**：全程在瀏覽器裡，電腦上什麼都不用裝
- **路徑二**：你電腦上要先有一個讀得到檔案的 AI 工具

### 路徑一・不需要懂程式

開始前先確認兩件事：

- **方案**：上傳自訂 skill 需要 claude.ai Pro 以上
- **設定**：到 <https://claude.ai/settings/capabilities>，把「Code execution and file creation」打開。要開這個，是因為整包規則是用檔案的形式運作的。沒開的話壓縮檔解不開、讀不到裡面的檔

接著三步：

1. **下載壓縮檔**：
   [civic-tech-writing-pipeline.zip](https://github.com/Legendream/AI-Writing-Skill/releases/latest/download/civic-tech-writing-pipeline.zip)
   。內容更新時這個檔案會自動換新，網址不變，所以可以放心存書籤
2. 開 <https://claude.ai/customize/skills>，把剛才下載的檔案上傳上去。
   claude.ai 把這種整包安裝的工作方式叫做「Skill」，介面上看到這個字，指的就是這份東西。找不到這個頁面的話，直接在設定裡搜尋 `Skills`
3. 開新對話，跟它說「**我想寫一篇公民科技相關的文章**」

### 路徑二・電腦上有 Claude Code、Antigravity 這類工具的人

開一個資料夾，跟 AI 說一句話：

> 請你把這個 repo 抓到這裡：<https://github.com/Legendream/AI-Writing-Skill>

（`repo` 就是 GitHub 上存放一整套檔案的地方，這裡指的就是上面那個網址。）

2026-08-18 我們就是這樣把它交給 Antigravity 的，後續跑完了一整篇文章。你只要打這一句，抓檔案的事交給 AI 做。

**你的素材放這個資料夾底下就好**：開一個叫 `素材` 的子資料夾，連結、訪談筆記、PDF 都丟進去。這類工具讀得到你電腦上的檔案，所以素材不用貼進對話，跟它說「素材在素材資料夾」就行。走路徑一的人不用做這件事，素材直接丟進對話裡。

抓完之後，**每次開始寫的時候跟它說一句**：

> 照你剛抓下來那包裡的 `civic-tech-writing-pipeline/SKILL.md` 進行

「你剛抓下來那包裡」這幾個字要講，它幫 AI 定位。抓下來會多一層資料夾，講清楚了它才找得到。那包的最外層還有一份同名的檔案，那只是路標，真正的流程在 `civic-tech-writing-pipeline`
資料夾裡面那一份。

覺得每次都要講很麻煩的話，可以請 AI 把 `civic-tech-writing-pipeline` 資料夾放進工具自己的 skills 資料夾（Claude Code 是 `~/.claude/skills/`，
Antigravity 是 `~/.gemini/config/skills/`），放進去它就會自己叫出來。**這個做法我們還沒實測**，上面那條抓到一般資料夾的做法才是驗證過的。

## 裝完之後，怎麼確認裝對了

開新對話之後，AI 不會立刻動筆，而是先問你主題與素材範圍、手上已有哪些素材，以及要寫哪一種文體。

**但「有問問題」不能當成裝成功的判準。**它本來就會問問題。就算完全沒裝成功，它也會問得很好、很像回事。我們自己實測時就被騙過：問題問得漂亮，但用的根本不是這套流程。

**可靠的判準只有一個**：看它回覆的**最後一行是不是以「下一站：」開頭**。例如：

```
下一站：素材盤點
```

站名會隨進度變（素材盤點、大綱、初稿⋯⋯），但「下一站：」這個開頭是規則裡寫死的，每一站結尾都會出現。有這一行就是裝成功了。兩條路徑都用同一個判準。

沒有這一行的話，看你走的是哪一條：

- **路徑一**：回頭確認第 2 步的壓縮檔是不是真的上傳好了
- **路徑二**：抓到一般資料夾的做法不會自動觸發，每次開始要跟它說上面那句話。已經說了還是沒走，多半是它找不到檔案：請它「先把 `SKILL.md` 開頭那段唸給我聽」，唸不出來就是路徑不對，請它自己找出正確路徑再重講一次

如果你的帳號裡還裝了其他寫作類的 skill，它們可能會搶走觸發。介面上那行灰色的「讀取⋯⋯」標籤**不可靠**：它的文字是臨時生成的，我們實測時看過三種不同寫法，其中一種還指向錯的 skill。一樣以最後那行為準。

## 常見問題

### 我用 ChatGPT 或 Gemini，可以用這套嗎？

可以當寫作指引參考。想讓 AI 自動照著流程走，用 claude.ai 效果最好。

差別在規則怎麼進到 AI 手上：claude.ai 上傳一次就裝成 Skill，會照規則寫的順序讀下去；
Custom GPT 與 Gem 是把規則當知識檔，讀法是挑看起來相關的段落。

**實際會發生什麼**：這套流程的第一件事，是先問你手上有哪些素材。挑段落的讀法容易先撈到後面的寫作技巧，於是 AI 就直接動筆了。寫出來的東西讀起來很順，你很容易就這樣收下。

**建議**：那包裡附了逐條檢查清單，兩種文體各有一份驗收員版。用 ChatGPT 或 Gemini 的話，自己拿那份清單對照成品，這道關卡改由你來守，流程照樣有效。

這一題目前是推論，**我們還沒實測**。

### 換一個 AI 工具跑，結果會一樣嗎？

不一樣，各有各的長處。想照流程走得順，用 Claude。

我們自己用下來的感覺：Claude 照流程走最順，該停下來問你的地方都會停；
Antigravity 在修稿階段的語句處理得更通順。

不管用哪一個，成品最後都要再找一雙眼睛看過。

### 那雙眼睛去哪裡找？

用 Claude Code 的話，走路徑二把整包抓到電腦上，裡面附了一份現成的檢查員設定檔，可以拿來當這雙眼睛。走路徑一下載壓縮檔的人不會拿到這個檔。

用聊天介面的話更簡單，不用另外裝工具，手上有那份檢查清單就行：**開一個全新對話，只貼「檢查清單」和「成品」，就這兩樣。**讓它第一次看到你的成品。全新對話從零開始，這正是它挑得出問題的原因。

要貼的那份清單在那包的 `checklists` 資料夾裡，檔名帶「驗收員版」的就是。方法論長文與領域資源指南各有一份，挑你寫的那一種。

**這個開新對話的做法我們還沒實測過**，寫在這裡是給你自己試的起點。

### 實際用起來像什麼？

像一人編輯站。把它當編輯用，不是當出稿機器：留時間跟它討論，也留時間查證。

三件事先講清楚：

- **開頭是一輪問答。** 它會先問你主題、手上有哪些素材、這篇寫給誰看，問完才動筆。這是刻意設計的。如果你要的是貼一句話就出稿，市面上有更快的做法
- **時間主要花在查證。** 草稿很快就有，真正吃時間的是回頭核對每一句話的出處
- **AI 自己檢查過的東西，要再找一雙眼睛看。** 我們實測時，AI 自己來回檢查了四輪，交出來之後另外找人看，還是找得出要修的地方

## 寫完之後可以放哪裡

這套流程實際產出了 11 篇行動指引，收在[台灣公民科技資料庫](https://civictech.tw/#know-how)的行動指引區。那一區目前共 31 則，來自不同作者。（11 篇這個數字來自作者本人，站上看得到其中 6 篇掛同一個帳號，其餘用不同 ID，從外面數不出來。）

這套流程也不是先設計好才拿來用的。那 11 篇是一邊寫、一邊發現哪裡會出錯，再回頭把規則補上，慢慢累積成現在這樣。

**你用它寫出來的文章也可以放上去**，讓更多人找得到。做法是把文章貼在 HackMD，再把連結加進[《公民科技行動指引 Guide》](https://g0v.hackmd.io/@jothon/guide)那份索引。這不是規定，要不要放由你決定。
