### 路徑 A：瀏覽器直接使用（免安裝程式）

無需安裝程式環境，全程於瀏覽器操作：

1. **檢查環境設定**：確認使用 claude.ai Pro 方案，並至 [Capabilities 設定頁](https://claude.ai/settings/capabilities) 開啟「Code execution and file creation」。
2. **下載 Skill 壓縮檔**：下載最新版本 [civic-tech-writing-pipeline.zip](https://github.com/Legendream/AI-Writing-Skill/releases/latest/download/civic-tech-writing-pipeline.zip)（此連結會自動指向最新穩定版）。
3. **上傳至 claude.ai**：進入 [Skills 設定頁面](https://claude.ai/customize/skills)，上傳下載的 zip 壓縮檔。
4. **啟動協作**：開啟新對話，輸入「我想寫一篇公民科技相關的文章」即可開始。

### 路徑 B：本機開發者路徑（適合習慣終端機的使用者）

直接載入專案資料夾，方便讀取本機大量素材：

1. **抓取專案檔案**：在終端機執行或請 AI 助理下載：
   ```bash
   git clone https://github.com/Legendream/AI-Writing-Skill.git
   ```
2. **準備素材**：在專案目錄下建立 `素材` 資料夾，將 PDF、筆記或連結清單存入該處。
3. **啟動協作**：對 AI 助理發送指令：
   ```text
   請照你剛抓下來那包裡的 civic-tech-writing-pipeline/SKILL.md 流程進行，素材位於素材資料夾。
   ```

</Section>

<Section {...sections[3]}>

啟動新對話後，AI 會詢問主題範圍、現有素材與文章文體。

AI 本來就會主動提問，就算完全沒載入成功，它也能順暢對話，因此**不能把「AI 有問問題」當作載入成功的判準**。

**關鍵判斷指標**：檢視 AI 每輪回覆的**最後一行是否以「下一站：」開頭**（例如：`下一站：素材盤點`）。這是本流程的核心狀態信號。

### 沒看到「下一站：」怎麼辦？

- **路徑 A（瀏覽器）**：回頭確認 zip 壓縮檔是否確實上傳成功，且 Capabilities 設定已開啟 Code execution。
- **路徑 B（本機）**：請 AI「先把 `civic-tech-writing-pipeline/SKILL.md` 開頭那段唸給我聽」，唸不出來代表讀取路徑不正確。

</Section>

  <Faq q="為什麼交付前必須由獨立 AI 驗收？">
    實務測試顯示，負責產製草稿的 AI 容易產生盲點。AI 自己來回檢查了四輪，交出來由沒看過草稿過程的獨立 AI 驗收，還是找得出要修的地方。因此，流程強制在第 ⑥ 站使用乾淨對話的獨立 AI，僅輸入「驗收清單」與「文章成品」進行客觀挑錯。
  </Faq>
  <Faq q="我用 ChatGPT 或 Gemini，可以用這套嗎？">
    claude.ai 上傳一次即可載入為 Skill，會依規則順序讀取；Custom GPT 與 Gem 是把規則當成參考文件，讀法是挑看起來相關的段落。這套流程的第一步是先盤點素材，挑段落的讀法容易先撈到後面的寫作技巧而直接動筆。目前這部分屬於推論，尚未正式實測。
  </Faq>
  <Faq q="實際用起來像什麼？">

  </Faq>
